# LAN-236 시나리오 캘린더 API 설계

## 목표

주간 스트립·월 격자 화면용 캘린더 API를 제공한다. 서버가 창(WEEK 7칸, MONTH은 그 달 1일~말일)을 완성해 반환하므로 클라이언트는 날짜 나열을 계산하지 않는다. 완료한 날에는 완료한 시나리오의 썸네일을, 미완료 오늘 칸에는 배정된 시나리오 ID만 내려준다.

## 정책

- 완료 기준은 LAN-219의 `user_scenario_access` 생성 이력이다. `granted_at`이 속한 날짜를 완료일로 본다.
- 날짜 계산은 `Asia/Seoul` 기준이다. 응답의 `today`가 서버 기준 오늘이며, 클라이언트는 기기 시계로 오늘을 판단하지 않는다.
- 창은 기준 날짜(`date`, 생략 시 오늘)가 포함되도록 계산한다.
  - `WEEK`: 기준 날짜가 속한 주의 일요일부터 7칸. 이웃 달 날짜가 섞여 나올 수 있다.
  - `MONTH`: 기준 날짜가 속한 달의 1일부터 말일까지만. 일(day) 부분은 무시하며, 이웃 달 날짜는 포함하지 않는다(월 격자 패딩은 클라이언트 몫이다).
- 모든 칸을 배열에 담는다. 완료하지 않은 날도 `completed=false`로 포함하며 길이는 WEEK 7 고정, MONTH은 그 달의 실제 일수(28~31)다.
- 완료일 칸에는 완료한 시나리오의 ID와 `scenario.thumbnail_url`을 담는다. 완료 이후 시나리오가 비활성화됐어도 썸네일은 그대로 노출한다.
- 미완료 오늘 칸에는 배정된 시나리오 ID(LAN-219 진행 정책의 현재 시나리오)만 담고 썸네일은 null이다. 오늘 카드는 완료 전까지 물음표로 가리는 UI이기 때문이다.
- 모든 시나리오를 완료한 사용자의 미완료 오늘 칸은 시나리오 ID도 null이다.
- 지난 날짜의 미완료·미배정과 미래 날짜는 모두 같은 빈 칸(`completed=false`, ID·썸네일 null)이다. 재도전 대상은 오늘 배정에 `RETRY`로 반영되므로 달력에서 따로 구분하지 않는다.
- 같은 날 복습 권한이 복수로 생성된 경우 — 정책상 하루 1건이지만 — `granted_at` 오름차순 첫 건의 시나리오를 사용한다.
- `startedAt`은 사용자가 처음 시나리오를 완료한 날이다. 완료 이력이 없으면 null이고, 클라이언트는 이 경우 오늘 이전 칸을 완전히 비워 표시한다.
- `label`은 기준 날짜가 속한 달을 기준으로 만든다. `MONTH`은 "2026년 7월", `WEEK`은 "2026년 7월 5주차" 형식이며, 그 달 1일이 포함된 주(일요일 시작)를 1주차로 센다. 같은 창이라도 기준 날짜의 달에 따라 "2026년 7월 5주차"(date=07-30) 또는 "2026년 8월 1주차"(date=08-01)로 표기된다.
- 미래 날짜 조회도 정상 응답한다(전부 `completed=false`).

## API 계약

`GET /api/v1/scenarios/calendar?type={type}&date={date}`

요청 파라미터:

- `type`: `WEEK` 또는 `MONTH`. 필수.
- `date`: `yyyy-MM-dd`. 선택. 생략하면 서버 기준 오늘. 이 날짜가 포함된 창을 반환한다.

응답 필드:

- `type`, `date`(기준 날짜, 생략 시 오늘이 담김), `label`, `today`, `startedAt`(없으면 null)
- `days[]`: 창의 모든 칸, 날짜 오름차순. 각 칸은 `date`, `completed`, `scenarioId`, `thumbnailUrl`.
- `scenarioId`가 null이 아닌 칸은 완료한 날들과 (배정이 있는) 오늘뿐이다.

`type` 값 오류와 `date` 형식 오류(불가능한 월 포함)는 400으로 응답한다.

## 데이터 구조

새 테이블은 없다. `user_scenario_access`와 `scenario.thumbnail_url`을 조회만 한다.

- 완료 이력 구간 조회와 첫 완료일 조회는 learning 기능의 `UserScenarioAccessRepository`에 있다.
- 오늘 배정 시나리오는 content 기능의 `ScenarioProgressionService.findCurrentScenario`를 재사용한다.
- 썸네일 매핑은 content 기능이 `Scenario`를 ID로 조회해 수행한다.

## 제외 범위

- 스트릭 카운트 계산.
- 클라이언트 표시 규칙(흐리게, 물음표, 빈 칸)의 판별. 서버는 데이터만 내려준다.
- 알림, 위젯 등 스트릭 활용 기능.
