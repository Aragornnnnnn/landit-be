# LAN-298 편지함 어드민 기능 구현 계획

## 목표

- 어드민이 공지·업데이트를 초안으로 만들고 수정·게시·게시 중단·상단 고정한다.
- 피드백을 검색·필터링하고 여러 사용자에게 같은 답장을 한 번에 전달한다.
- 모든 쓰기 작업을 기존 어드민 감사 로그에 기록한다.

자동 저장, 예약 게시, 버전 이력, 완전 삭제, 이미지, 답장 수정·삭제는 구현하지 않는다.

## API

```text
GET   /api/v1/admin/mailbox/letters
POST  /api/v1/admin/mailbox/letters
PATCH /api/v1/admin/mailbox/letters/{letterId}

GET   /api/v1/admin/mailbox/feedbacks
POST  /api/v1/admin/mailbox/replies
```

- 공지·업데이트 생성 상태는 `DRAFT`다.
- 수정 API는 콘텐츠, `publicationStatus`, `pinned` 중 전달된 값만 변경한다.
- 게시된 콘텐츠도 즉시 수정할 수 있다.
- 게시 중단 시 상단 고정을 해제하며, 고정은 `PUBLISHED` 상태에서만 허용한다.
- `contentBlocks`는 한 개 이상의 요소가 있는 JSON 배열로 검증한다.
- 목록 응답에 편집 데이터를 포함해 별도 상세 API를 만들지 않는다.

## 피드백 조회

- 본문 키워드, 유형, 처리 상태, 작성 기간으로 검색·필터링한다.
- 페이지 번호 방식으로 조회하며 기본 20건, 최대 100건을 허용한다.
- 전체 건수와 전체 페이지 수를 반환한다.
- 정렬은 최신순과 오래된 순만 허용한다.

## 일괄 답장

1. 선택한 피드백을 잠금 조회하고 존재 여부를 검증한다.
2. 사용자별로 묶고 `createdAt`, `id`가 가장 작은 피드백을 대표 건으로 정한다.
3. 답장 편지 한 건과 사용자별 수신 정보 한 건을 저장한다.
4. 선택된 `PENDING` 피드백을 `COMPLETED`로 변경하고 나머지 `PENDING` 건을 대표 건과 연결한다.
5. 기존 `COMPLETED` 피드백의 상태와 대표 연결은 유지한다.
6. 답장과 상태 변경, 감사 로그를 하나의 트랜잭션으로 처리한다.

같은 피드백을 다시 선택해 추가 답장을 보낼 수 있다. 감사 로그에는 본문이나 개인정보 대신 대상 ID와 처리 건수만 저장한다.
