# LAN-474 배포 중 학습 보존.

2026-09-11 결제 ON 통합 검증 계획: FE develop `c62be093`의 API·구독 훅을 수정 없이 로컬 BE HTTP 서버와 연결한다. H2와 실제 AI HTTP 라우터를 사용하며 외부 LLM·스토어만 대역으로 둔다. 첫 무료 대화·피드백·결제 웹훅·표현 완료와 구독 조회 실패·반영 지연·구버전 진입을 재현한다. 서버 권한을 완화하지 않고 BE·AI에서 가능한 오류만 보정한다. 운영 배포·SSM 변경·실결제는 수행하지 않는다.

기준은 #181·#182가 병합된 develop과 운영 hotfix 역병합 #185다. #183의 미래 시각까지 비활성 정책도 공통 공개 서비스에서 유지한다. #183 자체는 별도 PR로 남아 있다.

## 구현.

- 첫 무료 시나리오를 시작할 때 사용자 잠금 아래 한 세션에 예약한다. 중도 종료·서버 오류는 같은 세션에서 재개하며 원래 시작 후 24시간을 연장하지 않는다.
- 시나리오·스몰톡·표현 시작 권한을 DB에 저장한다. 구독 변경 뒤에도 유효한 기존 학습은 이어가고, 접수한 작업의 결과 저장은 새 시작 제한과 분리한다.
- AI 메시지 평가 요청·완성 결과·평가 근거를 DB에 보관한다. 기존 백그라운드 호출을 사용하므로 일반 턴의 다음 질문은 기다리지 않는다. 임대 만료 재시도와 이전 응답 차단을 적용한다.
- AI 캐시가 없으면 완료 세션의 저장 발화로 평가를 재예약한다. 최종 AI 통신 실패는 빈 결과로 확정하지 않고 재시도한다. 스몰톡 표현 PREPARING도 만료된 시도만 복구한다.
- 결제 공개는 기존 SSM `LANDIT_SUBSCRIPTION_LAUNCHED_AT`과 FE `NEXT_PUBLIC_PAYMENT_ENABLED`로 유지한다. DB 공개 정책과 관리자 변경 API는 제거한다. 오픈 시각이 없으면 학습 제한과 무료 기회 차감이 없다.
- 실제 구독 만료 시각, 샌드박스 무시, AI 내부 인증 헤더와 정상 종료를 연결했다. 기존 RevenueCat TRANSFER 처리를 재사용한다.

## FE 연동.

- 기존 `/api/v1/me/subscription`의 `premium`을 재사용한다. `paymentEnabled`로 공개 여부, `canStartScenario`로 새 대화, `freeScenarioSessionId`로 기존 무료 대화 재개를 구분한다. `newStartsPaused`는 이번 범위에서 항상 false다.
- 시나리오 메시지에 `clientMessageId` UUID를 보내고 오류·응답 유실 시 같은 ID·내용·입력 방식으로 재전송한다. 저장된 응답은 그대로 재생한다. ID 없는 기존 FE는 AI 실패 후 다시 녹음한 다른 내용도 제출할 수 있다. 성공 응답 유실의 완전한 중복 방지는 보장하지 않는다.
- 표현 learning-start의 `learningAttemptId`, `learningExpiresAt`를 저장한다. 연습·발음·완료 요청에 `X-Learning-Attempt-Id`를 유지한다. 완료 저장 시에도 잠금 안에서 ID를 확인한다. 헤더 없는 구버전은 마지막 소유 시도로 판정한다.
- 앱 복귀·로그인 변경·PREMIUM_REQUIRED 뒤에는 구독 정책을 다시 조회한다. FE 구현과 실기기 검증은 이번 변경에 포함하지 않았다.

## 전환과 검증.

- dev 테스트 → 심사 → 숨김 출시 → 오픈을 유지한다. 선배포는 SSM 오픈 시각을 비워 기존 FE로 사용한다. 심사·숨김은 기존 FE 플래그로 제어한다. 오픈할 때 SSM 시각 반영 후 BE를 재기동하고 FE 플래그를 켠다. 롤백은 시각 비우기·BE 재기동과 FE 플래그 끄기를 함께 한다. 저장한 무료 예약·실결제 권한은 보존한다.
- 오픈 후 기존 학습의 24시간 재개 UI까지 보장하려면 FE가 해당 세션을 이어 열고 허용된 학습을 페이월로 막지 않도록 별도 연동해야 한다. 결제 비활성 선배포와 구분한다.
- V100~V104는 열린 PR #182의 V98·V99 다음이다. 구 BE가 남은 첫 롤링 교체 중 만든 오픈 전 세션도 서버 시작 기록으로 24시간 유예를 판정한다. 이미 시작한 구버전 표현에는 시작 기록이 없어 소급 유예가 불가능하므로 최초 전환 때 기존 표현을 마치고 새 learning-start를 거치게 한다.
- AI 응답 fixture를 실제 AI 테스트 엔드포인트에서 생성해 DB 저장·최종 요청 재사용을 검증했다. 동시 무료 시작, 중도 재개, 24시간 경계, 동일 메시지 재시도, 임대 교체·늦은 응답, SSM 비활성·오픈 시각·롤백, 구버전 FE 재녹음, 구독 만료, 샌드박스·내부 인증을 테스트한다.
- `./gradlew check`가 통과했다. 테스트 1,156개 중 실패 0·생략 4개이며 Spotless·Checkstyle도 통과했다. `.github/scripts/test`의 배포 revision Python 테스트 3개와 ECS 검증 shell 테스트도 통과했다.
- 운영 workflow의 digest revision 등록에는 배포 역할의 추가 IAM 권한이 필요하다. 해당 IAM 코드 작성은 자동 승인 검토가 거절해 미포함이며, 권한 준비 전 운영 workflow를 실행하면 안 된다. AWS apply·배포·SSM 변경·실결제 검증은 수행하지 않았다.

2026-09-11 후속 점검: DB 공개 제어를 제거하고 기존 FE의 재녹음·만료된 시도 교체를 복구했다. 재현 테스트의 실패를 확인한 뒤 수정했고 `./gradlew spotlessApply check`를 47초에 통과했다. 로컬 H2 테스트 1,156개 중 실패 0·생략 4개다. 기존 정상 대화와 무료 예약은 보존하며, 키 있는 메시지의 동일 요청 재생 계약도 유지한다. 이번 보정은 주 에이전트가 직접 검토했다.

## 결제 ON 통합 테스트 결과 (2026-09-11).

FE develop `c62be093` 소스는 수정하지 않았다. FE API·구독/구매 훅 → 실제 BE HTTP 서버(H2) → 실제 AI HTTP 서버를 연결했다. 외부 LLM 응답·스토어 브릿지·라우터 이동은 테스트 대역이다. 화면 렌더링 전체, 실기기 결제, 운영 SSM 전환은 검증하지 않았다.

- 정상 5개: 첫 무료 대화→캐시 제거 후 피드백→모델 수준 평가→페이월→구매 웹훅→표현 완료, 시작 후 구독 만료 시 대화·표현 완료, AI 실패 후 기존 FE의 다른 내용 재제출, 같은 무료 세션 재개 API, 구매 취소·활성 구독 복원.
- 웹훅 지연: FE는 확인 중 안내 후 실제 복귀 지점인 표현 목록으로 이동한다. 목록 조회는 200이고 학습을 다시 누르면 페이월로 막히며, 웹훅 반영 후 학습이 열린다. 지연만으로 학습 API 오류가 나는 것은 아니다.
- FE 오류 경로 3개를 재현했다: 구독 조회 실패 뒤 학습 진입, 브라우저 진입, 강제 업데이트로 진입을 차단하지 않은 1.2.x 진입. 모두 FE는 이동을 허용하지만 BE는 `403 PREMIUM_REQUIRED`로 거부한다. 테스트의 성공은 **이 문제가 재현된다는 뜻**이며 안전하게 출시할 수 있다는 뜻이 아니다. 같은 세션 재개 API의 성공도 FE의 녹음·질문 진행도 복원까지 보장하지 않는다.
- BE 오류 1건을 수정했다: 공용 요청 DTO에 추가한 `completedFeedbacks`가 수준 평가 요청에도 들어가 실제 AI가 `400 extra_forbidden`을 반환했다. BE가 수준 평가에 필요한 4개 필드만 보내도록 수정했다. 수정 전 `source=FALLBACK`, 수정 후 `source=MODEL`을 실제 HTTP 통합 테스트로 확인했다. 기존 최종 피드백의 저장 결과 전달은 유지한다.
- 회귀 검증: `./gradlew spotlessApply check` 통과(62초). BE 1,158개(실패 0, 생략 4), AI 539개(실패 0, 생략 7). FE 통합 9개는 정상 흐름 5개, 웹훅 지연 시 재차단 1개, 오류 재현 3개를 합친 수다. 사용자 요청에 따라 주 에이전트가 직접 수정·검토했다. FE·AI 운영 소스, 구독 권한, SSM·플래그 정책 변경은 없다.

재실행은 [통합 테스트 실행 방법](../../../scripts/integration/README.md)을 따른다. FE를 유지하는 현재 범위에서는 정상 흐름 검증과 BE 계약 보정까지 완료했고, 위 FE 오류 경로는 남아 있다.
