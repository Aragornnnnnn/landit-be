# LAN-566 기억 생성의 시간·토큰 예산과 재시도 정책 개선

- `origin/main`의 `47c7c10`에서 `hotfix/LAN-566`을 생성했다. 기존 작업 공간의 변경은 보존한다.
- AI 후보 생성 전체 예산 50초와 판정 전체 예산 20초에 전송 여유 5초를 더해 BE timeout을 각각 55초·25초로 분리한다. 일반 대화의 설정값과 기억 검색 임베딩 2초는 유지한다.
- AI 내부의 호출별 제한·토큰·재시도 정책은 AI `docs/tasks/LAN-566/plan.md`가 기준이다. 두 endpoint를 모두 호출하면 BE HTTP 대기 상한 합계는 80초이며 DB 작업 시간을 포함한 전체 작업 deadline은 아니다.
- 재현 과정에서 `HttpRequest.timeout`만으로 헤더 수신 이후 지연된 본문을 제한하지 못함을 확인했다. 공통 클라이언트가 응답 본문 완료까지 기존 제한 시간으로 기다리고 timeout·인터럽트 시 전송 future를 취소하도록 보완한다. 일반 요청의 설정 시간 자체는 바꾸지 않는다.
- AI 오류는 기존 실패 계약으로 전달한다. 잘못된 후보를 저장하거나 빈 후보 성공으로 바꾸지 않으며 대화 완료 상태를 유지한다. BE 재시도는 추가하지 않는다.
- 재현 테스트: 기억 전용 timeout 미전달, 일반 timeout의 오적용, 느린 응답 본문의 제한 초과 3건이 기존 코드에서 실패했다.
- 로컬 HTTP 서버·mock으로 전용 timeout, 짧은 일반 timeout과의 독립성, 헤더 이후 본문 지연, 기존 임베딩 제한을 검증한다. 기억 생성 실패 시 저장 제외와 도메인 대화 완료 상태 유지도 확인한다.
- 전체 `./gradlew check`를 실행하고 결과를 아래에 기록한다. 실제 LLM 호출·운영 DB 변경·배포는 이 작업에 포함하지 않는다.
