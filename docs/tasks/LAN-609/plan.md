# LAN-609 BE·AI 하위 호환성과 혼합 버전 배포

## 범위와 결정

- 기존 5단계와 신규 100점 평가를 재설계하지 않는다. 응답 계약, 실제 척도에 따른 BE 집계·승급, 단계별 활성화만 추가한다.
- BE는 `X-Landit-Assessment-Version` 헤더로 계약을 요청한다. 기본 설정 `LANDIT_AI_ASSESSMENT_VERSION=text-level-v1.3`은 기존 평가를 유지한다. 신형은 `text-score-v2.0`이다. JSON 본문은 기존 AI가 허용하는 필드만 유지한다.
- AI는 헤더가 없으면 기존 루브릭으로 level 1~5를 직접 생성한다. 명시적인 v2 요청만 기존 develop의 score 1~100 생성 경로를 사용한다. 두 평가를 함께 호출하거나 산술 환산하지 않는다.
- BE는 응답 필드와 버전으로 척도를 확인한다. 구형 AI가 헤더를 무시해도 level 응답은 기존 정책으로 처리한다. 작은 score 값을 level로 오인하지 않으며 혼합 필드·부정확한 타입·범위·버전은 거부한다.
- 기존 평가는 반올림, 질문 상한 2/4/5, 승급 기준 현재 수준+0.7을 유지한다. 신형은 기존 develop의 20점 구간, 상한 40/80/100, 승급 기준 현재 수준×20+4를 유지한다. 다른 척도의 연속 승급 신호는 합산하지 않는다.
- 저장 시 실제 assessmentVersion을 기록한다. 기존 scoreMax 응답과 과거 기록 무환산 조회를 유지한다. DB 스키마 추가 변경은 없다.
- AI 총평은 구형 BE의 필수 highlightMessage를 이미 생성한 summaryMessage로 제공한다. 추가 모델 호출은 없다.

## 구현 순서

1. AI 계약 선택, 기존 루브릭 복원, 재시도/필터/직렬화의 척도 보존.
2. BE 양방향 응답 처리, 정책 선택, 활성화 설정, 승급 신호 분리.
3. HTTP 혼합 버전·정상/비정상 평가·저장 조회·OpenAPI 회귀 검증.
4. 전체 BE check, AI unittest, 변경 검토 및 논리 단위 커밋.

## 배포 및 롤백 경계

- 기준 구형은 운영 BE main의 text-level-v1.3, AI c2ebd326의 level 계약이다. 중간 develop(v2 전용)의 혼재는 별도 조합이며 안전 기본값을 보장하지 않는다.
- 1단계: 기본 v1 설정으로 호환 BE와 호환 AI를 배포한다. 이 두 호환 빌드는 어느 쪽부터 배포해도 운영 구형과 계약이 맞는다. 새 평가가 v1로 저장되는지 확인한다.
- 2단계: 모든 BE/AI 인스턴스가 호환 빌드이고 FE가 scoreMax=5/100을 표시하는지 확인한 후 BE 설정을 v2로 변경한다. 일부 BE 인스턴스만 v2로 전환되어도 두 척도를 읽고 저장한다.
- 3단계: 필요 시 BE 설정을 v1으로 되돌릴 수 있다. 이미 저장한 v2 기록은 환산하거나 삭제하지 않는다.
- v2 기록 생성 후에는 scoreMax를 모르는 원래 구형 BE로 바이너리 롤백하지 않는다. 호환 BE 빌드를 롤백 기준으로 유지한다. 구형 런타임의 Flyway 이력 검증 및 DB 운영 적합성은 배포 점검에서 별도로 확인한다.
- 운영 배포, 실사용자 요청, 실제 LLM의 평가 동등성은 로컬 회귀 테스트와 별개다.

## 검증 결과

- Java 21 `./gradlew cleanTest spotlessApply check --offline --console=plain` 통과: 총 1,929건, 성공 1,917건, 조건부 제외 12건, 실패·오류 0건. Spotless, Checkstyle, 아키텍처 검사도 통과했다.
- 단위/HTTP 검증: 기본 헤더와 v2 헤더, 구형 AI의 헤더 무시, 작은 score의 척도 보존, null 미관찰, 잘못된 숫자 타입·범위·혼합 척도·버전 및 세션 불일치 거부.
- H2/API 통합 검증: v1 저장 → v2 전환 → v1 복귀, 실제 assessmentVersion/scoreMax 및 값 보존, 척도 간 승급 신호 분리, 과거 결과 조회 시 추가 평가 없음.
- AI 전체 unittest: 총 847건, 성공 840건, 조건부 제외 7건. 최종 스키마 메타데이터 변경 후 관련 165건도 통과했다.
- 별도 로컬 HTTP 대조: 원형 구형 BE `cfb15ec066277ed0baa255395c02c6c0500e99d7`의 실제 클라이언트/DTO를 컴파일하고, 구형 AI `c2ebd3268c329eb7fb677ca3cb00c66e10dd92f1` 및 호환 AI 라우터에 연결했다. 아래 5개 조합 모두 평가 필드·척도와 총평 수용이 통과했다.
  - 구형 BE → 호환 AI 기본 v1.
  - 호환 BE v1 → 호환 AI v1.
  - 호환 BE v2 → 호환 AI v2.
  - 호환 BE v1 → 구형 AI v1.
  - 호환 BE v2 → 구형 AI v1(헤더 무시).
- 위 HTTP 대조는 수준 평가 생성의 LLM 출력만 테스트 fixture로 대체했다. 총평은 라우터에 응답 모델을 주입해 직렬화/소비 계약을 확인했고, 총평 생성 자체는 AI unittest로 검증했다. 운영 런타임이나 모델 품질 검증은 아니다.
- 초기 전체 실행 중 로컬 테스트 결과 파일 경합이 발생해 해당 실행 결과를 사용하지 않고 단일 `cleanTest ... check`로 재검증했다. AI 루프백 서버 테스트는 소켓 접근이 가능한 환경에서 전체 실행했다.
- GitHub CI와 운영 배포는 위 로컬 결과와 별개다.
