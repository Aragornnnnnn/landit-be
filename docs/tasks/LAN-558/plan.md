# LAN-558 Sentry 진단 정보 개선

## 승인된 범위

- 사용자 요청: Sentry에서 자세한 예외 사항을 확인할 수 있게 BE와 AI 관측 경로를 개선한다.
- 민감정보 제거, 최종 실패/정상 복구 분류, API 응답과 fallback 동작은 유지한다.
- 예외 타입과 원인 스택, 허용된 검증 사유/필드, 외부 HTTP 상태를 남긴다.
- 프리톡 교정 코드 오류 누락, 일반 BE 로그의 그룹화 충돌, 요청 ID 전파를 보완한다.
- 모델 응답 원문, 발화, 프롬프트, 인증 정보는 수집하지 않는다.

## 구현과 검증

1. AI 공통 진단 필터와 수준 평가/교정/속마음 실패 원인 보존.
2. BE 공통 이벤트 정보, 외부 AI HTTP 오류, 알림/첨부 정리 보고 경로 보완.
3. SDK 메모리 전송으로 상세 정보 보존과 민감정보 제외를 함께 검증.
4. AI 전체 unittest와 BE `./gradlew check` 실행 후 저장소별 커밋.

## 변경 내용

- Sentry 제목과 최상위 예외 메시지에 기능/단계/고정 사유를 표시한다. 원인 타입과 스택은 유지하고 원문·본문·로컬 변수는 제외한다.
- 공통 AI 클라이언트와 시나리오 AI 클라이언트가 HTTP 실패 상태를 `AiUpstreamException`에 보존한다. 공개 오류 코드는 유지하고 정상 400/409 거절에는 원인을 추가하지 않아 기존 보고 분류를 유지한다.
- `error_code`와 `upstream_status`를 원인 정제 전에 추출하고 일반 SDK 직접 보고에도 적용한다. 보고 후 MDC는 원래 값으로 복원한다.
- 일반 오류 로그의 기본 그룹화 지문에 logger를 포함한다. 알림 예약/편지 답장 큐/정기 알림/첨부 정리 경로는 명시적인 기능·단계·원인 예외를 보고한다.
- AI 구현과 상세 이벤트 예시는 landit-ai의 `docs/tasks/LAN-558/plan.md`에 기록했다.

## 검증 결과

- `./gradlew spotlessApply check` 통과. 225개 테스트 클래스, 1,771개 중 1,759개 통과, 12개 기존 조건부 제외, 실패/오류 0개.
- SDK 메모리 전송으로 원인 스택, HTTP 상태/오류 코드 보존, 민감정보 제외, MDC 복원, 태그 없는 다른 logger의 그룹 분리를 확인했다.
- 로컬 HTTP 서버로 두 AI 클라이언트의 401/429/500/503 원인 상태 보존과 기존 공개 오류 코드 유지를 검증했다. 기존 400/409 거절은 cause가 없음을 확인했다.
- 기존 정상 복구/중복 억제, 알림/피드백 테스트를 포함한 전체 검사가 통과했다.
- 운영 Sentry 전송, 배포, 실제 provider 호출은 수행하지 않았다. 변경은 배포 후 새로 발생하는 이벤트부터 적용되며 과거 이벤트의 제거된 상세 정보는 복원하지 못한다.
