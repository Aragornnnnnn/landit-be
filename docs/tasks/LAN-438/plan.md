# LAN-438 공통 온보딩 진단 4문항

## 확정 계약

- 시나리오 1 신규 시작은 사용자 수준 미설정 또는 1~5 모두 같은 4문항이다.
- 질문과 번역 원문은 onboarding-questions.json을 기준으로 한다.
- 질문 묶음 DIAGNOSTIC은 사용자 수준이 아니다. 최초 수준 평가는 1~5 전체 범위다.
- 신규 시작과 목록·일일·관리자 미리보기는 공통 진단 묶음을 사용한다.
- 과거 세션은 저장된 질문 그룹과 3문항 구성을 유지한다. 기존 질문·번역·메타데이터·음원을 덮어쓰거나 비활성화하지 않는다.
- 4문항의 실제 답변 모두 평가하며 기존 Core/Details, 충분성, 초기화·승급·Fallback 계약을 유지한다.
- 사용자 수준 선택 화면 삭제는 FE 작업이다. 기존 사용자 설정 API 삭제는 포함하지 않는다.

## 질문별 평가 메타데이터

| 질문 | 응답 요구도 | 필수 응답 요소 |
| --- | --- | --- |
| 1 | MEDIUM | 하는 일, 여가 활동. 이름은 필수로 추가하지 않는다. |
| 2 | MEDIUM | 최근 즐겁거나 기억에 남는 경험. 없었다는 응답도 허용한다. |
| 3 | HIGH | 가고 싶은 여행지와 이유. |
| 4 | HIGH | 혼자 여행과 친구와의 여행에 대한 의견. 명시하지 않은 이유·반론을 필수로 추가하지 않는다. |

## 구현과 검증

- 공통 그룹 CHECK 제약 추가, 신규 시작과 미리보기 조회 변경.
- 기존 세션 후속 질문과 평가 메타데이터는 저장된 그룹으로 조회.
- 수준 미설정 및 1~5 각각 4문항 진행·마지막 턴 완료·평가 입력 4건 통합 테스트.
- 진단 그룹의 Level 1~5 평가 범위 및 기존 그룹 질문 보존 회귀 테스트.
- 독립 검수에서 기존 그룹 덮어쓰기 위험을 발견해 별도 DIAGNOSTIC 그룹으로 보완.
- 최종 `./gradlew spotlessApply check` 통과. 실제 V87 SQL 실행, 수준 미설정·1~5의 공통 질문 진행, 기존 세션 질문 수 3 보존을 검증했다.
- V86/V87, 질문·번역·메타데이터·음원 URL까지 포함한 독립 재검수에서 추가 blocker 없음.

## 데이터·음원

- 사용자 승인에 따라 OpenRouter deepgram/aura-2, aura-2-hyperion-en으로 Marco 음원을 제작했다.
- google/gemini-2.5-pro에 정답 없이 실제 MP3를 전달해 블라인드 전사와 음질 판정을 받았다.
- 대소문자·구두점을 정규화한 단어열이 원문과 일치하고, 명료함·완결성 true, 결함 없음, 자연스러움 4 이상일 때만 게시했다.
- 2번의 So 누락 전사, 4번의 단어 불일치·재생성본 클릭음 지적을 받아 재생성했다. 최종 4개는 전사 일치·결함 없음·자연스러움 5다. 모델 검증이며 사람 청취 검수 완료를 뜻하지 않는다.
- MP3 4개를 landit-content-982529430654의 content/scenarios/1/diagnostic-questions/ 아래 새 fingerprint 경로에 게시했다. DB ID는 identity로 배정하므로 경로에 임의 질문 ID를 사용하지 않는다.
- 모든 CloudFront URL의 전체 바이트 SHA-256, audio/mpeg, Range 206을 확인했다. 기존 객체 덮어쓰기는 없다.
- audio-verification.json에 실제 모델, 요청 ID, 전사, 음질 판정, 길이, 해시, URL을 보존한다.
- V86은 DIAGNOSTIC 그룹을 허용한다. V87은 기존 질문을 보존하고 신규 4문항·음원·평가 메타데이터와 total_question_count=4를 등록한다.
- 운영 DB 마이그레이션과 앱 배포는 실행하지 않았다.
- 오디오 입력 계약 참고: https://openrouter.ai/docs/guides/overview/multimodal/audio
