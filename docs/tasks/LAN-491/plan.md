# LAN-491 한국어 퀴즈 복수 정답 데이터 작업.

## 확정한 범위.

- 원본은 `writing_expression_rows.csv`이며 표현 3,000개, 예문 12,000개이다.
- 한국어 퀴즈에 사용될 수 있는 각 표현의 1·2번 예문 6,000개만 작업한다. 현재 서버는 앞의 두 예문에 영어와 한국어를 요청마다 하나씩 배정한다.
- 3·4번 예문 6,000개, 영어 데이터, 질문·번역·이미지·대표 문장과 원본 CSV는 보존한다.
- 대상 안에서 한국어 오답이 4개인 33개 예문만 오답 1개를 제거한다. 대상 밖의 오답 4개인 예문 18개는 유지한다.
- 오답이 1개·2개·3개인 보기 배열은 바꾸지 않는다.
- 기존 정답을 유지하고, 같은 단어 조각과 중복 횟수로 구성되는 자연스럽고 의미가 같은 어순을 가능한 만큼 추가한다. 추가 개수에 상한을 두거나 대표 변형 한 개만으로 검토를 끝내지 않는다.
- 초기 단계에서는 유형별 샘플 20~30개로 결과를 확인한 뒤 전수 작업에 적용한다. 이번 결과는 추가 개수 제한 없이 재검토한 30개 샘플과 오답 제거 33개 초안이다.

## 데이터 형식 초안.

기존 `sentenceTranslateWords`는 1차원 배열 그대로 유지한다. 새로운 `sentenceTranslateAcceptedAnswers`는 기존 정답을 첫 원소로 포함하는 2차원 배열로 제안한다. 다른 어순을 추가하지 않는 문장도 기존 정답 하나를 담는다. 필드명과 API 매핑은 데이터 검토 뒤 구현 단계에서 확정한다.

JSONL의 `expressionId`와 `practiceExampleNumber`로 원본 예문을 식별한다. 예문 순번은 1부터 시작하며 이번 변경 대상은 1 또는 2뿐이다. 모든 레코드의 `REVIEW_READY`는 검토할 수 있는 초안이라는 뜻이며 DB 반영 상태가 아니다.

- `sample-answers.jsonl`: 문맥, 기존 정답, 복수 정답 후보, 판단 근거와 제외 예시를 담은 30개 샘플이다. 함께 오답 제거 대상인 7개는 제거 후 보기 배열을 담는다. `reviewPass: 2`는 이번 재검토 회차이며 `rejectedAnswerExamples`는 허용 배열과 구분되는 검토용 근거이다.
- `distractor-removals.jsonl`: 제거할 오답 1개와 변경 전후 보기 배열, 제거 이유를 담은 33개 패치이다.
- `sample-review.md`: 두 JSONL의 내용을 사람이 읽고 검토할 수 있도록 정리한 문서이다.

## 어순 검토 기준.

- 주어·목적어·시간·장소·수단 등을 옮기더라도 행위의 주체, 대상, 시점, 부정 및 수식 범위가 같아야 한다.
- 관형절, 수량구, 관용 표현과 보조 용언 내부를 임의로 분리하지 않는다.
- 주어·목적어의 교환뿐 아니라 부사 위치, 조건절의 위치, 자연스러운 구어 후치와 두 문장의 순서 교환도 검토한다. 특정 위치를 일률적으로 고정해 후보를 줄이지 않는다.
- 구어에서 한 성분을 술어 뒤에 자연스럽게 덧붙일 수 있으면 포함한다. 여러 성분을 뒤에 쌓아 인위적으로 끊어 읽어야 하는 배열은 포함하지 않는다. 원본처럼 정답 배열에는 문장부호를 넣지 않는다.
- 두 문장 이상의 답안은 각 문장을 보존한 채 순서를 바꾸어도 질문 문맥과 논리 관계가 같고 자연스러운지 확인한다. 아니를 뒤로 보내 앞의 내용을 취소하는 등 담화 의미가 바뀌는 어순은 제외한다.
- `yes/no`와 긍정·부정문이 맞지 않는 내용 오류는 별도 검토 대상으로 남긴다. 이번 단계에서 응답어나 번역을 바꾸지 않는다.
- 자동 순열 생성 결과를 그대로 정답에 넣지 않는다. 기계 검증은 단어 구성과 변경 범위를 확인하며 의미 검토를 대체하지 않는다.

## 재검토 결과와 검증.

- 복수 정답 샘플은 30개이다. 기존 정답을 포함해 총 173개 배열이며, 추가 정답은 143개이다. 29개 예문에 복수 정답을 제안하고 한 단어 문장인 표현 `48`의 예문 1만 단일 정답을 유지한다.
- 문장별 정답 수는 기존 정답을 포함해 1~24개이다. 이전 샘플의 52개 배열을 모두 보존하고 121개를 더 추가했다. 허용 배열과 구분되는 제외 예시 28개도 이유와 함께 기록했다.
- 표현 `1944`의 두 예문은 각각 기존 정답 포함 2개를 유지했다. 개수 상한 때문이 아니라 관형절과 본절의 관계를 보존하는 자연스러운 변형을 검토한 결과이다.
- 정답 개수는 문장별 자연스러움과 의미 보존을 검토한 결과에 따라 결정했다. 주어·목적어·부사·조건절의 위치와 구어 어순, 문장 순서까지 검토하고 제외 예시에는 이유를 기록했다.
- 사용자 피드백의 달리기·영화 문장은 표현 ID `1944`의 1·2번 예문에서 확인해 샘플에 포함했다.
- 나머지 5,970개는 복수 정답 의미 검토 전이다. 전체 6,000개 작업 완료로 집계하지 않는다.
- 대상 6,000개의 기존 오답 개수는 1개 306건, 2개 521건, 3개 5,140건, 4개 33건이다.
- 33개 제거안을 메모리상 복사본에 적용하면 오답 1개 306건, 2개 521건, 3개 5,173건이 된다.
- 모든 추가 정답이 기존 단어 배열과 중복 횟수까지 같고, 보기에 포함되는지 확인했다. 기존 정답이 첫 원소로 남아 있고 정답 배열 간 중복이 없는지도 확인했다.
- 제외 예시 28개도 원본과 같은 단어 조각을 사용하며 허용 배열과 겹치지 않는지 확인했다. 제외 예시는 잘못된 단어 추가가 아니라 어순·의미 문제를 보여준다.
- 제거하는 단어는 정답에 없으며 보기에서 정확히 1회만 등장한다. 제거 후 정답 단어의 개수와 남은 보기 순서가 보존되는지 확인했다.
- 샘플과 제거안을 함께 적용한 메모리상 복사본에서 변경 예문은 중복을 제외한 56개이다. 변경 필드는 `sentenceTranslateAcceptedAnswers`와 `sentenceTranslateWordChoices`로 제한했다.
- 나머지 필드와 3·4번 예문 6,000개가 원본과 같은지 비교했다. JSONL 저장 후 재파싱한 내용도 생성 전 레코드와 대조했다. 이번 재검토에서 오답 제거안 파일의 바이트는 변경하지 않았다.
- 원본 CSV의 바이트가 작업 전후 같은지 확인했다. SHA-256은 `1f99b02b83038327907e7c5885e79da4f7b0a0219e2fc036279e68f0b6ad336e`이다.
- 이번 변경은 검토 문서와 JSONL 초안만 포함한다. 애플리케이션 코드, DB, API와 앱 채점은 변경하지 않아 Gradle 테스트를 실행하지 않았다. 데이터 검증과 Git diff 검토를 수행한다.

## 후속 순서.

1. 재검토 샘플의 자연스러움과 의미 보존에 대한 피드백을 반영한다.
2. 확정된 기준으로 남은 5,970개를 검토하고, 단일 정답 유지 사례도 완료 상태를 구분한다.
3. 전체 데이터의 정답 보존, 단어별 중복 횟수, 보기 정합성과 변경 범위를 다시 검증한다.
4. 데이터 구조를 기준으로 API 호환성과 앱 채점 변경을 설계한다.
