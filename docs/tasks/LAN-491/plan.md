# LAN-491 한국어 퀴즈 복수 정답 데이터와 마이그레이션.

## 확정한 범위.

- 원본 `writing_expression_rows.csv`의 표현 3,000개 가운데 각 표현의 1·2번 예문 6,000개를 검토했다. 현재 서버는 앞의 두 예문에 영어와 한국어 퀴즈를 요청마다 하나씩 배정한다.
- 기존 30개 샘플에 이어 남은 5,970개를 모두 검토했다. 사용자가 승인한 병렬 검토로 예문을 겹치지 않게 나누고, 결과를 통합했다.
- 원래 정답과 단어별 중복 횟수를 보존하면서 자연스럽고 의미가 같은 어순을 가능한 만큼 추가했다. 정답 개수 상한은 두지 않았다.
- 대상 안에서 한국어 오답이 4개인 33개 예문만 오답 1개를 제거했다. 오답이 1·2·3개인 보기와 대상 밖 오답 4개인 18개 예문의 보기는 그대로 유지했다.
- 데이터 검토 후 사용자의 요청에 따라 PostgreSQL V106 마이그레이션을 작성했다. 원본 CSV, 3·4번 예문 6,000개, 영어 데이터, 질문·번역·이미지·대표 문장과 애플리케이션 응답 코드는 그대로 유지한다. DB 실행은 폐기 가능한 로컬 검증 DB에서만 수행했다.

## 데이터 형식.

`expressionId`와 1부터 시작하는 `practiceExampleNumber`로 원본 예문을 식별한다. 이번 파일에는 순번 1 또는 2만 있다. 기존 `sentenceTranslateWords`는 1차원 배열 그대로 유지한다. 새 `sentenceTranslateAcceptedAnswers`는 원래 정답을 첫 원소로 포함하는 2차원 배열이다. 단일 정답 문장도 원본 하나를 담는 2차원 배열이다.

`sentenceTranslateWordChoices`에는 33개 대상의 오답을 하나씩 제거한 결과가 포함돼 있다. `distractor-removals.jsonl`은 변경 내역 확인용이며, 이미 변경된 보기에 중복 적용하지 않는다. 파일의 `REVIEW_READY`는 검토 가능한 데이터 상태이고 DB 반영 상태가 아니다. `reviewReason`과 `reviewNotes`는 검토용 정보이며 서비스 응답 필드로 추가한 것이 아니다.

DB의 복수 정답 필드명은 `sentenceTranslateAcceptedAnswers`로 반영한다. API 매핑과 실제 복수 정답 채점은 후속 구현 범위이다. 기존 1차원 정답·보기 응답의 파싱 호환성은 테스트로 확인한다.

## 의미·어순 검토 기준.

- 질문과 영어·한국어 문장을 함께 읽고 행위의 주체, 대상, 시점, 부정, 수량 및 수식 범위가 같은지 확인했다.
- 관형절, 수량구, 관용 표현과 보조 용언은 하나의 결합으로 유지했다. 부사 이동, 주어·목적어 교환, 조건 절의 위치와 자연스러운 구어 후치를 검토했다.
- 한 성분을 술어 뒤에 자연스럽게 덧붙일 수 있으면 허용했다. 여러 성분을 뒤에 쌓거나 내포절의 술어만 떼어내는 어색한 배열은 제외했다.
- 두 독립 문장의 순서 교환은 같은 대화 기능과 논리를 유지할 때만 허용했다. 응답어, 거절·취소, 원인과 결과의 의미를 바꾸는 순서는 제외했다.
- 단일 정답으로 남긴 예문도 다시 살펴, 명사절 내부를 나눌 수 없다는 이유로 명사절 전체의 자연스러운 이동을 놓친 경우는 보완했다.
- 토큰 인덱스는 직접 검토한 순서를 기록하는 수단으로 사용했다. 자동 순열을 의미 검토 없이 정답으로 넣지 않았다.
- 담당 검토와 통합 담당자의 교차 검토에서 수량 부사, 겹주어, 인용·조건 절의 범위와 후치를 확인했다. 예를 들어 두 번 확인했다의 두 번을 보내기 전에 앞으로 옮기는 순서, 나가도만 괜찮을까요 뒤로 보내는 순서를 제외했다.
- 사용자 제보의 달리기·영화 문장은 표현 `1944`의 1·2번 예문이다. 둘 다 관형절 내부 주어와 활동 범위를 교환하는 기존 2개 정답을 유지했다.
- yes/no와 긍정·부정문이 맞지 않는 문제와 번역 오류는 원문 메모로 남겼다. 같은 토큰을 재배열하는 이번 작업만으로 내용을 고칠 수 없는 사례이다.

## 검증 결과.

- 원본 표현 3,000개에 각각 예문 4개가 있고, 통합 결과에 대상 6,000개 키가 정확히 한 번씩 있는지 확인했다.
- 6,000개 모두 원래 정답이 첫 번째이며, 추가 정답이 원본과 단어별 중복 개수까지 같고, 정답 배열끼리 중복되지 않는지 확인했다.
- 모든 정답을 보기 배열로 만들 수 있는지 중복 단어를 고려해 검사했다.
- 오답 개수는 변경 전 1개 306건, 2개 521건, 3개 5,140건, 4개 33건에서 변경 후 1개 306건, 2개 521건, 3개 5,173건이 됐다.
- 33개 보기에서 정답에 없는 단어를 정확히 한 번 제거했고, 남은 보기 순서와 정답 토큰은 보존됐다. 다른 5,967개 보기 배열은 원본과 같았다.
- 전체 payload의 메모리상 복사본에 적용해 `sentenceTranslateAcceptedAnswers` 추가와 33개 `sentenceTranslateWordChoices` 변경 외의 필드가 같고, 3·4번 예문 6,000개가 그대로인지 비교했다.
- 저장한 JSONL을 다시 읽어 생성 결과와 비교했다. 검토용 CSV도 다시 파싱해 6,000행과 각 정답 문장이 같은지 확인했다.
- 기존 샘플 173개 정답을 그대로 포함했으며, 샘플 JSONL과 오답 제거 JSONL의 파일 바이트도 그대로였다.
- 원본 CSV의 SHA-256은 `1f99b02b83038327907e7c5885e79da4f7b0a0219e2fc036279e68f0b6ad336e`이며 작업 전후 동일했다.
- 데이터·문서 단계에서는 위 데이터 검증과 Git diff 검토를 수행했다. 이후 마이그레이션 단계의 실행 검증은 아래에 기록한다. 운영 DB 반영, API 변경, 앱 채점과 배포는 수행하지 않았다.

## V106 마이그레이션.

- 사용자가 지정한 [PR #189](https://github.com/Aragornnnnnn/landit-be/pull/189)의 `feat/LAN-461` 최신 커밋 `86acb036b0952e709dd16900547ed05f7455c150`을 기준으로 `feat/LAN-491`을 생성했다. 기존 데이터 커밋 3개는 그대로 옮기고, 원래 브랜치는 `backup/LAN-491-data-20260915`에 보존했다. 이 작업의 PR 기준 브랜치도 `feat/LAN-461`이다.
- 기준 브랜치의 마지막 마이그레이션은 V105이다. 새 파일은 `src/main/resources/db/postgresql/V106__add_korean_quiz_accepted_answers.sql`이며 기존 버전을 수정하지 않는다.
- `writing_expression.practice_examples_payload`는 기존 JSONB 컬럼이다. 테이블 컬럼과 JPA 엔티티 변경 없이 표현 3,000개의 1·2번 예문에 정답 배열 23,392개를 저장한다.
- 검토본의 6,000개 키, 원래 문장·번역·질문·정답·보기와 적용할 복수 정답을 SQL 내부에 고정했다. 33개 보기만 변경 전 배열을 별도 검토 파일에서 복원해 전제 조건으로 사용한다. 실행 시 외부 CSV나 검토 문서 파일을 읽지 않는다.
- Flyway 트랜잭션 안에서 `writing_expression` 쓰기 잠금을 잡고, 대상 표현의 존재·소스·예문 수 4개와 여섯 원문 필드의 정확한 JSONB 일치를 확인한다. 배열의 순서와 중복 횟수도 같아야 한다. 이미 복수 정답 키가 있는 대상은 덮어쓰지 않고 중단한다. 오류에는 처음 불일치한 표현 ID와 예문 번호를 남긴다.
- 대상 두 예문에 `sentenceTranslateAcceptedAnswers`를 추가하고, 승인된 `sentenceTranslateWordChoices`를 설정한다. 원래 `sentenceTranslateWords`와 나머지 예문 필드는 보존하고 대상 표현의 `updated_at`만 함께 갱신한다. 검토 당시 없던 표현이 DB에 추가돼 있어도 수정 대상에 포함하지 않는다.
- 적용 후 6,000개 정답·보기를 다시 대조한다. 추가한 키를 제거하고 보기만 복원했을 때 전체 payload가 적용 전과 같은지도 검사한다. 전제 조건이나 적용 후 검증이 실패하면 해당 버전 전체가 롤백된다. 성공한 V106은 Flyway 이력에 따라 재실행하지 않는다.
- JSONB SQL은 PostgreSQL 전용 경로에 두며 H2에는 적용하지 않는다. 기존 서버는 원래 정답과 보기를 계속 응답한다. 새 정답을 사용자 응답에 포함하고 복수 정답으로 채점하는 동작은 이 마이그레이션에 포함되지 않는다.

## 마이그레이션 검증.

- `Lan491KoreanQuizMigrationTests`는 SQL의 6,000개 매핑을 검토 JSONL과 전부 비교하고, 복수 정답의 원본 우선 순서·토큰별 중복 횟수·배열 중복·보기로 구성 가능 여부와 정확히 33개인 보기 수정을 검사한다. 기존 영어·한국어 응답 파싱도 검증한다.
- `Lan491KoreanQuizPostgresTests`는 별도 로컬 PostgreSQL 15.18에서 매번 독립 스키마를 만들고 V105로 baseline한 뒤 실제 Flyway로 V106을 실행한다. 정상 적용 및 재실행 생략, 대상 밖 표현 보존, 원문 불일치 9가지, 트리거로 유발한 적용 후 검증 실패 2가지를 검사한다. 실패 사례는 모든 표현 행이 적용 전과 같고 V106 성공 이력이 남지 않는지 확인한다.
- 원본 CSV의 3,000개 표현과 12,000개 실제 예문을 별도 로컬 스키마에 복원해 V106 SQL을 실행했다. 전체 payload를 검토본으로 만든 예상 결과와 비교해 모두 일치했다. 3·4번 예문 6,000개는 동일하고, 보기 수정은 33개, 저장된 정답은 23,392개였다. 원본 CSV의 체크섬도 변하지 않았다.
- 재현 시 전용 로컬 DB `lan491_test`, 사용자 `lan491_test`, 포트 `55491`을 준비한 뒤 다음 명령을 사용한다. PostgreSQL 테스트는 해당 환경 변수를 설정했을 때만 실행되며 운영 DB URL을 받지 않는다.

```bash
LAN491_TEST_POSTGRES_URL='jdbc:postgresql://127.0.0.1:55491/lan491_test?user=lan491_test' ./gradlew check
```

- 위 PostgreSQL 환경 변수를 설정한 `./gradlew spotlessApply check`가 통과했다. 전체 1,226개 중 1,220개 성공, 별도 환경 조건 6개 생략, 실패·오류 0개이다. 이번에 추가한 데이터·호환성 3개와 PostgreSQL 12개는 모두 실행해 통과했다. `git diff --check`와 원래 데이터 커밋 3개의 `range-diff`도 확인했다.
- 실제 운영 데이터의 현재 상태와 V1부터의 PostgreSQL 전체 마이그레이션 재생은 이 로컬 검증의 범위에 포함하지 않았다.

## 후속 구현 범위.

V106 배포와 별도로 API의 복수 정답 응답 및 앱 채점 방식을 구현한다. 원문 메모에 있는 yes/no 응답·번역 오류의 내용 수정은 별도 범위로 결정한다. 이 문서는 데이터와 마이그레이션의 범위·검토 기준·검증 결과의 기준 문서로 유지한다.
