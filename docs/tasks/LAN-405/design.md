# LAN-405 시나리오 질문 레벨 분리와 표현 난이도 노출 설계

## 목표

- 사용자 학습 수준에 맞는 시나리오 고정 질문을 제공한다.
- 레벨 1은 초등학생도 이해할 수 있는 쉬운 질문, 레벨 2~3은 중·고등학생 수준의 질문, 레벨 4~5는 기존 질문을 사용한다.
- 시나리오 표현은 기존 `writing_expression.difficulty_level`을 사용해 레벨 1, 레벨 2~3, 레벨 4~5의 노출 범위를 나눈다.
- 진행 중인 세션에서는 프로필 레벨이 바뀌어도 시작할 때 선택한 질문 수준을 유지한다.
- 기능 구현과 신규 질문·음원 데이터 삽입을 서로 다른 PR로 분리한다.

## 확정된 레벨 규칙

### 시나리오 질문

| 사용자 `learning_level` | 질문 그룹 |
| --- | --- |
| 1 | `LEVEL_1` |
| 2, 3 | `LEVEL_2_TO_3` |
| 4, 5, `null` | `LEVEL_4_TO_5` |

`user_profile.learning_level` 값은 변경하지 않는다. 애플리케이션이 조회 시점에 질문 그룹으로 해석한다.

### 시나리오 표현

`writing_expression.difficulty_level`은 1~5 범위의 표현 난이도다. 시나리오에서는 아래 범위로 그룹을 구분하며 별도 표현 레벨 그룹 필드는 추가하지 않는다. 프리톡의 최대 난이도 필터는 기존 정책을 유지한다.

| 사용자 `learning_level` | 허용하는 표현 |
| --- | --- |
| 1 | `difficulty_level = 1` |
| 2, 3 | `difficulty_level BETWEEN 2 AND 3` |
| 4, 5, `null` | `difficulty_level BETWEEN 4 AND 5` |

기존 시나리오 표현은 V76에서 난이도 4로 백필해 레벨 4~5 사용자에게 유지한다. 신규 표현 데이터는 각 사용자 레벨 그룹에 맞는 난이도로 적재한다.

## 데이터 모델

### `scenario_question`

- `question_level_group VARCHAR(30) NOT NULL`을 추가한다.
- 허용 값은 `LEVEL_1`, `LEVEL_2_TO_3`, `LEVEL_4_TO_5`로 제한한다.
- 기존 질문 120개는 모두 `LEVEL_4_TO_5`로 백필한다.
- 기존 유일 조건 `(scenario_id, display_order)`를 제거한다.
- 새 유일 조건 `(scenario_id, question_level_group, display_order)`를 추가한다.
- `display_order > 0` 제약과 기존 FK·상태 필드는 유지한다.

질문 문구, 번역, 음원 URL, AI 첫 질문의 속마음은 기존처럼 `scenario_question_language_variant`에 저장한다. 질문 그룹은 언어와 무관하므로 원형인 `scenario_question`에 둔다.

### `scenario_session`

- `question_level_group VARCHAR(30) NOT NULL`을 추가한다.
- 기존 시나리오 세션은 `LEVEL_4_TO_5`로 백필한다.
- 새 세션은 시작할 때 프로필 레벨에서 결정한 질문 그룹을 저장한다.

질문 그룹은 시나리오 세션에만 필요한 값이므로 FreeTalk도 함께 저장하는 `learning_session`에는 추가하지 않는다.

### `writing_expression`

새 필드를 추가하지 않는다. V73에서 추가된 다음 계약을 그대로 사용한다.

- `difficulty_level INTEGER NOT NULL`.
- `difficulty_level BETWEEN 1 AND 5` 체크 제약.
- `difficulty_level` 인덱스.

## 런타임 조회 흐름

### 시나리오 탐색과 첫 질문

시나리오 목록, 일일 시나리오, 관리자 테스트 목록은 현재 프로필의 학습 레벨을 질문 그룹으로 해석한 뒤 해당 그룹의 `display_order = 1` 질문을 조회한다. `learning_level = null`인 사용자는 기존 동작 보존을 위해 `LEVEL_4_TO_5` 질문을 사용한다.

공개 API 응답 구조는 변경하지 않는다. 기존 첫 질문 문구·번역·속마음·음원 URL 필드에 선택된 그룹의 데이터가 담긴다.

### 세션 시작과 후속 질문

1. 세션 시작 시 활성 사용자 프로필을 조회한다.
2. 프로필 레벨을 질문 그룹으로 해석한다.
3. 해당 그룹의 첫 질문을 포함한 시작 콘텐츠를 조회한다.
4. `scenario_session.question_level_group`에 선택한 그룹을 저장한다.
5. 두 번째·세 번째 질문은 프로필을 다시 해석하지 않고 세션에 저장된 그룹으로 조회한다.

따라서 사용자가 진행 중 프로필 레벨을 바꿔도 해당 세션은 시작 당시 질문 그룹을 끝까지 사용한다.

정확히 일치하는 그룹의 질문만 조회한다. 다른 그룹의 질문으로 자동 대체하지 않는다. 기능 PR만 적용된 상태에는 레벨 1~3 질문이 없으므로 실제 배포는 데이터 PR까지 준비된 뒤 진행한다.

### 시나리오 표현

시나리오 표현 목록, 학습 진행도, 표현 상세, 추가 연습, 완료 처리에서 사용자의 허용 난이도 범위를 적용한다.

- 레벨 1은 난이도 1.
- 레벨 2~3은 난이도 2~3.
- 레벨 4~5와 `null`은 난이도 4~5.

표현 ID를 직접 전달해도 사용자 난이도 범위 밖의 `SCENARIO` 표현은 학습하거나 완료할 수 없다. 완료 이력은 표현 ID 기준으로 유지하며, 현재 사용자에게 노출되는 표현만 진행도 분모와 완료 수에 포함한다. 알림 대상 집계도 같은 노출 규칙을 사용한다.

`FREE_TALK` 표현의 추천·조회·학습 흐름에는 시나리오 레벨 필터를 추가하지 않는다.

## PR 분리

### 기능 PR

브랜치는 `feat/LAN-405`를 사용하고 `develop`을 대상으로 한다.

- 질문 그룹 enum과 프로필 레벨 매핑 로직.
- `scenario_question`, `scenario_session` 스키마 변경과 기존 데이터 백필.
- PostgreSQL·H2 마이그레이션.
- 시나리오 목록·일일·관리자·세션 시작·후속 질문의 그룹별 조회.
- 기존 `writing_expression.difficulty_level` 기반 표현 노출·진행도·접근 검증.
- 관련 단위·저장소·API·DB 통합 테스트.
- 공개 API 응답 형식 유지.

신규 질문, 번역, 속마음, 음원 파일과 URL은 기능 PR에 넣지 않는다.

### 데이터 PR

기능 PR이 병합되고 기존 원격 작업 브랜치를 정리한 뒤, 최신 `develop`에서 `feat/LAN-405`를 다시 만들어 데이터 PR을 연다. 두 PR은 같은 이슈 브랜치 규칙을 순차적으로 사용하며 동시에 열지 않는다.

- 활성 시나리오 40개 각각에 `LEVEL_1` 질문 3개 추가.
- 활성 시나리오 40개 각각에 `LEVEL_2_TO_3` 질문 3개 추가.
- 신규 질문 240개, 영어 문구 240개, 한국어 번역 240개.
- AI First 시나리오의 각 레벨 첫 질문에 속마음과 `GOOD` 유형 추가.
- 승인된 텍스트로 캐릭터 음성에 맞는 MP3 240개 생성.
- 검증된 음원 URL을 포함한 Flyway 데이터 마이그레이션.

초보용 시나리오 표현을 새로 삽입하거나 기존 표현 난이도 분류를 바꾸는 작업은 데이터 PR 범위가 아니다.

## 질문 제작 계약

### 공통 규칙

- 시나리오별 고정 AI 발화는 각 그룹에 정확히 3개다.
- 영어 발화와 한국어 번역을 항상 한 쌍으로 관리한다.
- 영어 발화는 25단어 이하로 유지한다.
- 답변 소재는 현재 AI 발화, 사용자가 바로 떠올릴 수 있는 쉬운 취향, USER First 시작 안내 중 하나에서 얻을 수 있어야 한다.
- 가상의 과거, 일정, 예산, 소지품, 수치처럼 제공되지 않은 정보를 지어내게 하지 않는다.
- 고정 후속 발화가 사용자의 직전 자유 답변을 특정 방향으로 가정하지 않게 한다.
- 같은 결정을 반복해서 묻지 않고 마지막 발화는 목표 달성이나 다음 행동 확정으로 수렴한다.
- AI 역할이 실제로 제공할 수 있는 정보와 조치 범위 안에서 질문한다.

### `LEVEL_1`

- 쉬운 일상 단어와 짧고 직접적인 문장 구조를 사용한다.
- 한 발화에서 핵심 선택이나 요청 하나만 다룬다.
- 색상, 시간, 음식, 좌석, 간단한 취향처럼 즉시 답할 수 있는 내용을 우선한다.
- 추상적인 이유, 가치 판단, 복잡한 비교, 숨은 사정을 요구하지 않는다.

### `LEVEL_2_TO_3`

- 일상·학교·여행·서비스 상황에서 쓰는 익숙한 단어를 사용한다.
- 간단한 비교, 한 가지 이유 설명, 요청 조정은 허용한다.
- 사회적 쟁점, 윤리적 판단, 장기 계획처럼 추상적이거나 심오한 주제는 제외한다.
- 답변 부담을 늘리기 위한 불필요한 `왜` 질문은 사용하지 않는다.

## 텍스트 승인과 음원 작업

1. 실제 활성 시나리오 40개와 질문 ID 점유 상태를 다시 확인한다.
2. 두 질문 그룹의 영어 문구·한국어 번역·AI First 속마음을 작성한다.
3. 구조 검증과 질문별 의미 검수를 실행한다.
4. 사용자에게 전체 텍스트를 제시하고 승인을 받는다.
5. 승인된 텍스트로만 시나리오 캐릭터에 맞는 음성을 생성한다.
6. 질문 ID와 콘텐츠 해시를 포함한 불변 S3 키와 manifest를 만든다.
7. MP3 240개를 업로드하고 S3 메타데이터와 CloudFront 재생·Range 응답을 검증한다.
8. 검증된 전체 URL을 데이터 마이그레이션에 삽입한다.
9. DB 마이그레이션 테스트와 전체 검증을 통과한 뒤 데이터 PR을 연다.

텍스트 승인 전에는 음성을 생성하거나 업로드하지 않는다. 질문 ID, S3 키, URL은 실제 점유 상태와 업로드 결과 없이 임의로 만들지 않는다.

## 오류와 과도기 동작

- 요청한 질문 그룹의 데이터가 없으면 다른 그룹으로 대체하지 않고 기존 콘텐츠 없음 처리 흐름을 따른다.
- 허용 난이도보다 높은 시나리오 표현 ID에 직접 접근하면 리소스를 노출하지 않는다.
- `learning_level = null`은 질문과 표현 모두 기존 사용자 호환을 위해 레벨 4~5로 해석한다.
- 기존 진행 중 시나리오 세션은 마이그레이션에서 `LEVEL_4_TO_5`로 백필해 이어서 진행할 수 있게 한다.
- 기능 PR과 데이터 PR 사이 상태는 배포 완료 상태로 간주하지 않는다.

## 검증

### 기능 PR

- 프로필 레벨 1~5와 `null`의 질문 그룹·표현 난이도 범위 매핑을 단위 테스트한다.
- 같은 시나리오와 질문 순서에 세 그룹을 저장할 수 있고 같은 그룹의 중복은 거부되는지 DB 테스트한다.
- 기존 질문과 시나리오 세션의 `LEVEL_4_TO_5` 백필을 검증한다.
- 시나리오 목록·일일·관리자·세션 시작이 올바른 레벨의 첫 질문을 반환하는지 통합 테스트한다.
- 프로필 레벨을 세션 중 변경해도 후속 질문이 시작 당시 그룹을 유지하는지 통합 테스트한다.
- 레벨 1, 레벨 2~3, 레벨 4~5의 표현 목록·진행도·상세·연습·완료 접근을 통합 테스트한다.
- 알림용 표현 집계가 사용자에게 노출되는 난이도만 포함하는지 검증한다.
- FreeTalk 표현 흐름의 회귀 테스트를 실행한다.
- 최종적으로 `./gradlew check`를 실행한다.

### 데이터 PR

- 활성 시나리오 40개에 두 신규 그룹이 각각 존재하는지 검증한다.
- 그룹별 질문 120개, 신규 질문 240개, 전체 질문 360개인지 검증한다.
- 모든 그룹에서 시나리오별 `display_order`가 1~3으로 연속되는지 검증한다.
- 영어·한국어 문구 수, AI First 속마음, 상태, 로케일, 음원 URL의 누락과 중복을 검증한다.
- 모든 영어 발화가 25단어 이하인지 기계 검증한다.
- 답변 출처, 분기 독립성, 역할 현실성, 번역 자연스러움을 질문별로 의미 검수한다.
- manifest가 승인된 질문 240개와 일대일로 대응하고 ID·S3 키·해시가 중복되지 않는지 검증한다.
- MP3 파일과 캐릭터 음성의 일치, S3 객체 존재, CloudFront 응답과 Range 재생을 검증한다.
- `scenario_question_language_variant.audio_url` 누락이 0개인지 검증한다.
- 최종적으로 `./gradlew check`를 실행한다.
