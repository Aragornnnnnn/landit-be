# LAN-582 시나리오 총평 확장

## 확정 요구사항

- 시나리오 총평 응답에 해당 세션의 사용자 수준 평가 상태와 결과를 포함한다. 기존 비동기 평가 응답을 재사용하며, 점수는 1~5 척도를 유지한다.
- 잘한 점과 개선할 점은 현재 API 결과에서 선택값으로 유지한다. AI의 수준 평가 후보 모델에서는 두 설명을 필수로 요구하고, 최초 생성과 재시도 모두 생성하도록 요청한다.
- AI 설명이 누락되거나 비어 있으면 해당 후보를 정상 결과로 처리하지 않는다. 저장된 기존 결과·평가 전 상태·최종 생성 실패 대체 결과는 근거 없는 설명으로 채우지 않는다. 안전 검증 과정에서 설명을 제거해야 하는 결과는 선택값 정책에 따라 설명 없이 반환할 수 있다.
- 스몰톡의 실수 개선과 배운 표현 재사용을 시나리오 총평에도 포함한다.
- 비교 범위는 같은 사용자 프로필의 직전 완료 시나리오 1회다. 이번 세션 시작 시각까지 완료된 기록 가운데 종료 시각 내림차순, 세션 ID 내림차순으로 고른다. 주제·시나리오 ID·언어로 좁히지 않으며 스몰톡은 비교 대상에서 제외한다.
- 직전 세션의 실제 교정과 현재 발화의 같은 패턴 사용이 확인될 때만 `growthFeedback`을 반환한다. 직전 세션에 교정 근거가 없거나 현재 발화에서 비교 근거를 찾을 수 없으면 `null`을 반환하고, 더 오래된 세션으로 거슬러 올라가지 않는다.
- 배운 표현 후보는 시나리오 또는 스몰톡에서 학습 완료한 표현이다. 현재 발화에서 실제로 사용한 정확한 구절이 확인된 표현만 `expressionReuse.items`에 담는다.
- FE는 비교 결과가 `null`이면 카드를 숨기고, 표현 분석이 끝난 뒤 목록이 비어 있으면 카드를 숨긴다. 빈 상태 문구는 표시하지 않는다. 분석 중이면 로딩을 표시하고 FE 대기 시간이 초과되면 카드를 숨긴다.

## API·데이터 동작

- 총평 응답은 `userLevelAssessment`, nullable `growthFeedback`, `expressionReuse: { pending, items }`를 제공한다.
- 최종 총평 생성은 현재 BE 요청에서 완료된 뒤 저장된다. 따라서 완료 응답의 표현 분석은 `pending: false`이며, 결과가 없으면 `items: []`다. AI fallback 결과도 비교 카드와 표현 목록을 만들지 않는다.
- 새 비교 결과는 총평 JSONB 컬럼에 저장해 이후 조회에서 AI를 다시 호출하지 않는다. 기존 행은 nullable 비교와 빈 표현 목록으로 처리한다.
- AI가 반환한 메시지 ID와 인용 구절은 BE에서 입력 근거와 대조한다. 요청에 포함되지 않은 메시지나 원문에 없는 구절은 응답에서 제외한다.
- 원격 AI 요청에도 이전 교정과 학습 표현 후보를 포함하며 HTTP 계약 테스트로 전송을 확인한다. AI 출력 예산은 후보 수와 인용 길이에 따라 늘리고 최대 16K 토큰으로 제한한다.
- `nativeScore`의 100점 척도는 기존 의미를 유지하며 사용자 수준 점수로 변환하지 않는다.

## 구현 상태

- AI 수준 평가 후보에서 `details.strength`와 `details.improvement`를 필수화했고 최초 생성 및 재시도 스키마에 반영했다. 최종 응답은 근거 안전 필터링에 따라 해당 설명을 비울 수 있다.
- BE 시나리오 총평 응답에 기존 사용자 수준 평가 결과를 포함했다.
- BE가 직전 완료 시나리오의 실제 교정과 학습 완료 표현 후보를 AI에 전달하며, 검증한 비교·재사용 결과를 저장하고 반환한다.
- OpenAPI 문서와 통합 테스트를 갱신했다. FE 저장소는 현재 작업공간에 없어 UI 변경과 실제 카드 렌더링은 이번 BE·AI 검증 범위에 포함되지 않는다.

## 검증 경계

- AI 단위/API 계약과 BE 검사로 생성 후보, 저장 경로, 응답 형태를 확인한다.
- FE 저장소가 현재 작업공간에 없으므로 카드 숨김·로딩 UI와 실제 사용자 동작은 별도 FE 검증이 필요하다.
