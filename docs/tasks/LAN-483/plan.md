# LAN-483. 결제 도입과 수준 평가 활성화 연결.

## 확정 범위.

| 조건 | 동작 |
| --- | --- |
| `LANDIT_SUBSCRIPTION_LAUNCHED_AT` 미설정 | 수준 평가 예약·호출·복구 중단. 소유권 확인 후 조회 API는 `success: true, data: null, error: null`. |
| 신규 가입 또는 기존 수준 미설정 | 기본 수준 3. 이미 설정된 수준·과거 세션의 질문 그룹은 유지. |
| 도입 시점 이후 완료 | 기존 비동기 평가·fallback 실행. 최초 유효 평가만 기존/기본 수준 대체. |
| 이후 평가 | 기존 2회 연속 신호에 따른 한 단계 승급 유지. 자동 강등 없음. |

- 도입 전 평가 이력은 삭제하지 않되 최초 확정 이력에서 제외한다. 기준은 평가 저장 시각이 아닌 세션 완료 시각이다.
- 도입 전 완료된 예약을 조회·재시도해도 소급 평가하지 않는다.
- 결제자 여부와 무관한 전역 출시 설정이다. 무료 첫 진단도 평가한다.
- 기존 결제 설정처럼 서버 시작 시 값을 읽는다. 미래 시각을 넣어 자동 활성화하는 스케줄 기능은 추가하지 않는다.
- FE는 `data == null`이면 결과 UI와 polling을 종료해야 한다. 서버만으로 FE polling을 중단할 수는 없다.
- AI 프롬프트·가중치·임계값·시나리오 질문·음원 변경 없음. 실제 DB·환경변수 변경 및 배포 없음.

## 작업 순서.

1. 완료 예약, 실행, 조회/복구, 저장에 같은 출시 경계를 적용한다.
2. 출시 이후의 최초 확정 이력만 조회한다.
3. 프로필 기본값 3과 기존 NULL만 보정하는 마이그레이션을 추가한다. 구버전이 배포 중 NULL을 저장해도 현재 프로필 조회·알림 추천은 3으로 해석한다.
4. 비활성 null·소유권·평가 미실행, 활성화·최초 확정, 기본값·이력 보존을 회귀 검증한다.
5. 전체 `check`, 독립 검수, 커밋.

- `./gradlew spotlessApply check --no-parallel --console=plain`: 통과(48초).
- 테스트 1,114개: 성공 1,110개, 실패 0개, 기존 외부 PostgreSQL 조건부 제외 4개.
- 비활성 상태의 시나리오 1번 4문항 완료 → 피드백 조회 → 반복 수준 조회 `data:null`을 실제 Spring/H2 통합 흐름으로 검증. 수준 평가 AI 호출 0회, 평가 행 0개, 기본 수준 3 유지.
- 무인증 401, 타 사용자 403, 없는 세션 404 및 OpenAPI nullable 스키마 확인.
- 출시 경계 시각 포함·직전 제외, 출시 전 평가 이력 제외, 최초 대체 후 2회 승급, timeout fallback 회귀 통과.
- 비활성 완료 스냅샷 3과 과거 표현 그룹 보존 확인. 이후 현재 수준을 5로 바꿔도 과거 표현 그룹은 2~3 유지.
- 독립 검수에서 발견한 NULL 전환 경계와 과거 표현 수준 문제를 보완한 뒤 재검수 완료. 추가 차단 결함 없음.
