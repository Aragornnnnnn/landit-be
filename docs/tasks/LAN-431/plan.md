# LAN-431 프리톡 표현 742개와 이미지 게시

## 범위

- 사용자가 교정·검수한 프리톡 표현 742개(ID 2259~3000, 표시 순서 1776~2517)를 V94 하나로 추가한다.
- 이미 생성한 `openai/text-embedding-3-small` 1,536차원 임베딩 742개를 그대로 사용한다.
- 대표 이미지 742개와 각 표현의 추가 예문 3·4번 이미지 1,484개를 새 UUID S3 키로 게시한다. 추가 예문 1·2번 이미지 URL은 `null`이다.
- 기존 콘텐츠와 이미지 객체는 변경하지 않는다. 발음 자산 생성, DB 적용, PR 병합은 이번 범위에 포함하지 않는다.
- 운영 스키마에서 이미 삭제된 소유자 사용자 컬럼을 INSERT에 포함하지 않는다.

## 원본과 기준

- 기준 브랜치: `origin/develop` (`bf7377bc`). 공통·PostgreSQL 마이그레이션의 마지막 버전은 V93이다.
- 교정 CSV SHA-256: `bda458c58ba342ddaeabe193eda0f72228980ac95c53dc2f9179062fffec6f64`.
- 이미지 검수 기록의 SHA-256과 게시할 PNG/WebP를 대조했다. 대표 1448×1086, 추가 예문 1254×1254 규격과 이미지 디코딩을 전수 검사했다.
- 대표 이미지 최종 승인은 사용자 개별 승인과 마지막 인체 구조 중심 승인 기준을 반영한다. 게시 검증을 새로운 시각 품질 검수로 간주하지 않는다.
- 2026-09-11 읽기 전용 사전 확인: 개발 DB V93, 운영 DB V81, 양쪽 최대 표현 ID 2258. 이번 ID 구간과 프리톡 표시 순서 구간 충돌은 모두 0건이다.

## 실행 및 검증

1. 승인 파일 해시 검사와 불변 게시 매니페스트 확정.
2. S3 업로드 후 모든 객체의 크기·SHA-256 체크섬·MIME·캐시 정책 검사.
3. CloudFront GET 본문 SHA-256과 로컬 파일 전수 비교.
4. V94의 단일 INSERT, ID/표시 순서 충돌 차단, 삽입 후 계약 검증, 시퀀스 역행 방지 구현.
5. 데이터 계약 회귀 테스트, 실제 PostgreSQL·pgvector 실행 및 독립 검토.
6. `develop` 대상 PR 준비. 적용은 리뷰·병합 후 별도 배포 절차를 따른다.
