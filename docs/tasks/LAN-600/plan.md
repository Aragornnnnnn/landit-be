# LAN-600 스몰톡 직접 종료 API

## 계약과 구현

- `POST /api/v1/free-talk/sessions/{sessionId}/complete`는 본문 없이 200을 반환한다. 진행 중·종료 확인 대기를 완료하고, 이미 완료된 세션은 변경하지 않는다. 타인 403, 없는 프리톡 404, INTERRUPTED 409(CONFLICT), 미인증 401이다.
- 기존 `learning_session.completion_reason VARCHAR(30)`에 `DIRECT_COMPLETION`을 저장한다. 기존 작별 완료 `USER_ENDED`, 시간 소진 `TIME_LIMIT_REACHED`는 유지한다. 기존 컬럼으로 표현 가능하므로 Flyway 변경이 없다.
- 학습 세션·프리톡·이력·누적 발화 시간·스트릭을 같은 트랜잭션에서 확정한다. 제목이 없으면 기존 캐릭터별 대체 제목을 쓴다.
- 커밋 후 미확정 발화 교정, 기존 맞춤 표현·장기기억 생성 서비스를 비동기로 호출한다. 장기기억은 기존 write-enabled 설정을 따른다. 요약 총평은 기존 summary 조회 시 교정 대기·pending·계산 정책을 따른다.
- 완료는 구독·생성 요청 한도와 무관하게 가능하다. 세션 소유권과 상태는 완료 서비스에서 검증한다.

## 동시 요청 경계

- 서버가 발화 예약 트랜잭션에서 저장한 사용자 발화를 보존한다. 완료가 발화 저장보다 먼저 잠금을 획득하면 이후 신규 발화는 거부한다. 네트워크에 전송됐지만 서버에 아직 저장되지 않은 발화의 순서는 보장하지 않는다.
- 직접 완료는 AI 턴·closing 응답을 기다리지 않는다. 진행 중 발화와 종료 확인 대상 발화의 교정을 준비하고 완료 상태를 기록한다. 늦은 AI 확정은 마무리 메시지를 추가하거나 완료 상태·시각·사유·발화 시간을 덮어쓰지 않는다.
- 기존 발화 AI 호출이 실패해도 직접 완료로 보존된 발화와 사용 시간은 되돌리지 않는다. 직접 완료 후 발화 재전송은 AI 메시지가 없는 완료 결과를 허용한다.
- 발화 예약·확정·보상·직접 완료·표현 재시도의 잠금 순서를 사용자 프로필 → 세션 순서로 맞춘다. 소유 세션을 처음부터 잠금 조회하여 대기 전에 읽은 영속 엔티티 상태를 재사용하지 않는다.
- 반복 직접 완료는 교정·표현·장기기억 작업을 다시 등록하지 않는다. 발화 경로에서 이미 실행 중인 교정 결과와 직접 종료 교정 결과가 겹치면 기존 조건부 저장이 중복 반영을 막는다.

## 검증

- API 통합 테스트: 일반·빈 세션, 종료 확인 대기, 직접 완료 재시도, 기존 작별·시간 소진 완료 재시도, 미인증·타인·없는 세션·중단 세션, 완료 이후 발화 거부, 목록·상세·요약·스트릭, OpenAPI 계약.
- AI 응답을 latch로 정지한 동안 직접 완료가 반환되는지 검증하고, 이후 AI 성공·실패 모두 저장 발화와 완료 상태·누적 시간 보존을 확인한다.
- 구독 만료 후 직접 완료·재시도 회귀 테스트를 포함한다.
- Java 21에서 `./gradlew spotlessApply check --offline --console=plain` 통과: 1,799건, 실패·오류 0건, 제외 12건. `git diff --check` 통과.
- 장기기억 후속 질문 통합 테스트에서 `USER_ENDED`와 `DIRECT_COMPLETION` 모두 기존 `USER_CONFIRMED` AI 계약으로 전달됨을 확인했다.
- 실제 PostgreSQL 잠금, 원격 AI, FE 화면, 배포는 이 로컬 검증에 포함하지 않는다.
